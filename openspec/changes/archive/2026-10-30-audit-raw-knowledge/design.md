# Design

The independent OKF bundle groups durable concepts by product, architecture and runtime behavior with pinned source URLs. The requirements inventory maps each eligible raw source to a topic and lists draft requirement IDs with evidence and unresolved conflicts. OpenSpec records selected testable contracts, not approval of all historical source claims. The new audit skill supplies a reusable method for future work.

No public interface, runtime dependency, production code or UI behavior changes. External-context claims remain unverified against the external repository. The inventory maps files rather than verifying every claim. Outstanding questions and contradictory claims are recorded in the requirements inventory rather than resolved by assumption.

No ADR is needed: this applies the existing OKF/OpenSpec setup without deciding a new runtime architecture. Verification consists of OKF validation, OpenSpec validation, source-inventory checks and focused existing tests; tests do not establish full source or spec coverage.
